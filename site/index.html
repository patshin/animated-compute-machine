M10 · INTEROPERABILITY WITHOUT ARCHITECTURE CONFUSION

PROTOCOL DECK

One agent product may use several protocols, but protocols do not define the business state machine. Identify the communication boundary first, then choose a protocol; orchestration, authorization, business state, and evaluation remain owned by the runtime and application.

BOUNDARY RULE
Protocol = interoperable message contract.
Runtime = business orchestration + state.
Policy = permission + approval authority.

Do not treat MCP, A2A, or AG-UI as a shortcut to a capable agent.

MCP

AGENT ↔ CAPABILITY

Discover and call tools, resources, or prompt templates; use it to connect reusable capabilities.

HOST → CLIENT → SERVER
tools · resources · prompts
NOT: business workflow engine or authorization source

A2A

AGENT ↔ AGENT

Discover, delegate, track task state, and exchange artifacts across agents; use it only when independent ownership truly exists.

CLIENT AGENT ⇄ REMOTE AGENT
card · task · artifact
NOT: excuse to split one graph into chatty micro-agents

AG-UI

AGENT ↔ FRONTEND

Project runtime events, state patches, messages, and interactions into an observable human interface.

RUNTIME → EVENT STREAM → UI
run · message · state · tool
NOT: canonical backend state or database

OTEL

SYSTEM ↔ TELEMETRY

Observe model, tool, retrieval, and policy boundaries with traces, spans, metrics, and logs.

TRACE → SPANS → ATTRIBUTES
provider · tool · policy · eval
NOT: product event schema or learner-facing explanation
DECISIONUSE WHENKEEP OUTSIDE
MCPReusable tools and resourcesBusiness routing and user permission
A2ACross-deployment or cross-team delegationSplitting nodes inside one application
AG-UIReal-time frontend projection and interactionCanonical server-side state
OTELCross-component observation and correlationBusiness facts and final judgment
MISSION · DRAW THE BOUNDARY
1Choose a real application and mark its agent, tools, frontend, and remote agents.
2Place protocols only at system boundaries; keep the business state machine in the runtime.
3Write failure, permission, timeout, and observability requirements for every edge.
